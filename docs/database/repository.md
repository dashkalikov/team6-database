# Размещение документации в репозитории

## Комплект VC-65

В общий репозиторий проекта переносится каталог docs/database целиком:

```text
docs/
  database/
    README.md
    schema.mmd
    mermaid-code.md
    round-transaction.mmd
    data-dictionary.md
    django-schema.md
    design.md
    repository.md
    diagrams/
      er-diagram.pdf
      er-diagram.svg
```

Корневой README проекта содержит ссылку на docs/database/README.md. Если для БД выделен отдельный репозиторий, структура docs/database сохраняется; корневой README описывает назначение репозитория и указывает, где находятся серверные модели и миграции. Модели и миграции должны иметь один источник, без независимо редактируемых копий в нескольких репозиториях.

Файл schema.mmd является исходником диаграммы. Каталог diagrams содержит PDF ER-диаграммы и SVG-изображение, встроенное в словарь данных. Оба файла передаются в репозиторий вместе с документацией. При изменении схемы экспорты обновляются вместе с исходником. SVG обновлён до редакции 07.11.2026; er-diagram.pdf сохранён как архив предыдущей редакции и не используется как актуальная иллюстрация. Актуальный источник — schema.mmd. Если используется draw.io, редактируемый .drawio также сохраняется; в текущем комплекте он отсутствует.

## Файлы вне репозитория

Не переносятся:

- Каталог work: резервные копии приложений и локальные копии сторонних репозиториев для анализа.
- Файлы .env, пароли, ключи, токены, настройки DBeaver с учётными данными.
- Каталог данных PostgreSQL, дампы с рабочими данными, журналы и резервные копии.
- Установщики Python, PostgreSQL, DBeaver и расширений.
- Виртуальные окружения .venv, кеши Python и локальные временные файлы.

## Исключения Git

Для нового репозитория проекта используется следующий базовый набор .gitignore; в существующий файл правила добавляются с сохранением командных настроек:

```gitignore
work/
.env
.env.*
!.env.example
.venv/
venv/
__pycache__/
*.py[cod]
.pytest_cache/
.mypy_cache/
.ruff_cache/
data/postgres/
backups/
*.dump
*.log
```

.env.example содержит только названия переменных и безопасные примеры без рабочих учётных данных. SQL-файлы миграций и каталог migrations не исключаются из Git.

## Изменения после VC-65

При реализации в серверный проект добавляются модели, миграции, тесты, зафиксированные зависимости и инструкция запуска. Модель и соответствующая миграция передаются в одном изменении. Словарь и диаграмма обновляются при изменении структуры. Файлы с реальными данными БД для передачи структуры не используются.
